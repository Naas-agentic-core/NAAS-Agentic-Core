# Core Testing
# ⛔ The pytest quartet is held (#2296 proposed pytest 9.1.1 / pytest-asyncio
# 1.4.0 / pytest-cov 7.1.0 / pytest-env 1.7.0). pytest-asyncio 1.0 stopped
# honouring a user-defined `event_loop` fixture, and this suite's loop model
# depends on it: `tests/conftest.py:90` owns `event_loop`, and the autouse
# `db_lifecycle` fixture drives `_reset_db()` on it via `run_until_complete`.
# Under 1.4.0 the fixtures keep using that loop while the test body runs on a
# loop pytest-asyncio creates, so the cached aiosqlite engine is used from a
# loop it was not created on:
#     ValueError: no active connection  (aiosqlite/core.py:137)
#   -> sqlite3.OperationalError: no active connection
#   raised in tests/conftest_support/lifecycle.py:40, i.e. at fixture setup for
#   every DB-touching test, and the run deadlocks on the first TestClient one.
# Realigning loop ownership means rewriting the shared harness that ~4,800
# tests depend on (D-258 governs that file); it is its own change with its own
# issue, not a dependency bump. python-dotenv follows: its only reason to move
# was pytest-env 1.7.0's floor.
# Tracked for removal in #2303 (loop ownership + unregistered hooks).
